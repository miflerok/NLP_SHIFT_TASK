# NLP_SHIFT_TASK

## Описание

Тестовое задание по классификации текстовых обращений клиентов банка.

Цель проекта — определить намерение  пользователя по
диалогу с банковской поддержкой.

Модель должна учитывать не только последнее сообщение пользователя,
но и контекст предыдущих реплик диалога.

---

## Постановка задачи

Необходимо:

- сгенерировать синтетический набор банковских диалогов;
- сформировать 15 классов пользовательских намерений;
- обучить модель классификации текста;
- оценить качество модели на отложенной тестовой выборке;
- проанализировать ошибки классификации.

---

## Генерация данных

Для генерации синтетических диалогов используется открытая
языковая модель:

`IlyaGusev/saiga_llama3_8b_gguf`

Модель запускается локально в формате GGUF с использованием
`llama.cpp`.

Каждый диалог состоит из трех реплик:

1. сообщение пользователя;
2. ответ оператора;
3. финальное сообщение пользователя.

Целевой класс определяется намерением, выраженным в последнем
сообщении пользователя.

После генерации каждый пример проходит проверку структуры и
соответствия заданному классу.

---

## Датасет

Используется 15 классов банковских обращений.

Данные разделены на три выборки:

| Выборка | Количество примеров |
|---------|---------------------:|
| Train | 300 |
| Validation | 150 |
| Test | 150 |

На каждый класс приходится:

| Выборка | Примеров на класс |
|---------|------------------:|
| Train | 20 |
| Validation | 10 |
| Test | 10 |

### Назначение выборок

**Train** используется для обучения модели.

**Validation** используется во время обучения для контроля качества.

**Test** не используется при выборе модели и применяется только
после завершения обучения для получения финальной оценки.

---

## Модель

Для классификации используется:

`cointegrated/rubert-tiny2`

Это компактная русскоязычная transformer encoder-модель.

На основе предобученной модели создается классификатор
для 15 классов.

В качестве входа используется весь текст диалога.

---

## Обучение

Для обучения используется библиотека
Hugging Face Transformers и класс `Trainer`.

Основные параметры:

| Параметр | Значение |
|---|---:|
| Train batch size | 8 |
| Eval batch size | 8 |
| Learning rate | 2e-5 |
| Maximum epochs | 60 |
| Evaluation strategy | epoch |
| Save strategy | epoch |
| Weight decay | 0.001 |
| Early stopping patience | 3 |

60 эпох задаются как максимальное количество эпох.
При отсутствии улучшения validation-метрики используется
Early Stopping.

После обучения автоматически загружается checkpoint
с лучшим результатом на validation.

---

## Метрики

Для оценки используются:
- Accuracy
- F1
- Precision / Recall / F1 для каждого класса
- Confusion Matrix

---

## Результаты

Финальная оценка проводится на тестовой выборке.

В рамках тестового задания был реализован полный цикл классификации банковских обращений: от генерации и валидации синтетического датасета с помощью LLM до обучения и оценки модели.

Было сгенерировано **600 диалогов** по **15 банковским темам**. Для классификации последнего сообщения пользователя в контексте диалога использовалась модель **ruBERT-tiny2**.

Модель показала следующие результаты:

| Метрика | Значение |
|---|---:|
| Accuracy | **94.00%** |
| F1 | **93.97%** |

На тестовой выборке из **150 диалогов** модель правильно классифицировала **141 обращение**.

Лучше всего модель справилась с классами, связанными с курсом валют, блокировкой карты, восстановлением пароля, справками и выписками, инвестициями и безопасностью — **F1 до 1.00**.

Основные ошибки возникали между близкими по смыслу категориями, например комиссиями и лимитами на переводы, досрочным погашением кредита, условиями открытия вклада и условиями получения кредита.

**Итог:** модель показала стабильное качество около **93–94%** на validation и test выборках и продемонстрировала хорошую способность обобщать банковские обращения.

Подробный `отчёт и итоги`, графики обучения
и `confusion matrix` представлены в ноутбуке.
